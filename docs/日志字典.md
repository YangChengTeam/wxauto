# 日志字典 —— 每一条日志在说什么

> 招聘分身客户端（Windows）打出来的**每一条**日志，按「一次请求从哪来、到哪去」排列。
> 共 160 条事件。看到不认识的一行，直接在本文搜那句话。
>
> 日志文件：`%LOCALAPPDATA%\.wxclient\logs\gateway-YYYY-MM-DD.log`，一天一个，**留 30 天**。
> 界面里的「实时日志」页看到的是同一份内容。

## 0. 一行日志的结构

```text
2026-08-15 22:48:52 [信息] 好友申请已提交：13800138000（张三-仓库工）
└─── 时间 ──────┘ └级别┘ └──────────── 正文（中文，含关键值）────────────┘

2026-08-15 22:50:10 [警告] 界面卡了一下，stalled_ms=795，service="stopped"，page="log"
                                        └──────── 参数：key=value，逗号分隔 ────────┘
```

- **时间**是本机时间（不是 UTC），跨零点自动换文件。
- **级别**五档：`调试` / `信息` / `警告` / `错误` / `严重`。默认只记 `信息` 及以上，`调试` 要开 debug 才有。
- **正文**是渲染好的中文句子；**参数**是没有被写进句子的那些字段，原样 `key=value` 附在后面。
- 出异常时，异常栈**另起一行**接在同一条日志下面。

> 判断严重程度只看级别：`警告` = 这件事没做成但机器还能继续干；`错误` = 这条线断了（网关退出、租约丢失）。

## 1. 客户端 ↔ 业务后端（5 个 HTTP 请求）

契约见 `招聘分身_客户端认证与状态接口_v1.1.md`。这一族的日志回答「这台机器算不算在线、还有没有资格干活」。

| 日志 | 什么时候出现 | 字段 | 看到之后 |
|---|---|---|---|
| `已登录，user=张娟，agent=7152a0be…` | 邮箱密码登录成功 | `user` 显示名；`agent` 分身 ID（截断 8 位） | 正常。往下才会起网关 |
| `客户端会话已被撤销` | 任何一次上报吃到 `401 CLIENT_SESSION_REVOKED` | — | 管理员撤了、被别的电脑顶了、或账号停用。本机 Token 已就地清掉 |
| `客户端会话已失效，回到登录页` | 上一条之后界面的动作 | — | 停服务 + 回登录页。要人重新输密码 |
| `已上报客户端状态，status=online，reason=service_running` | 客户端状态**变化**时（不是心跳） | `status` = `online`/`offline`/`error`；`reason` 机器码 | 正常。企业端那一格跟着变 |
| `上报客户端状态失败，error=…，code=…` | 网络抖、服务端 5xx | `code` 服务端稳定错误码 | 会自动重试（沿用同一个幂等键） |
| `上报客户端状态被拒：重发也不会变，先不重试，details=…` | 400 / 409 | `details` 是服务端指出的**具体字段** | **不会重试**。照 `details` 修内容，光看正文只会得到一句「格式不对」 |
| `已上报微信连接状态，status=connected，capability=passed` | 微信 UIA 状态变化时 | `status` 五档；`failure` 失败码；`capability` = `passed`/`limited`/`failed` | `passed` 才会让企业端进「运行中」 |
| `上报微信连接状态失败 / 被拒` | 同上 | 同上 | 同上 |
| `退出前上报离线超时，先走了` | 退出时那次 `offline` 3 秒没送到 | — | 企业端可能还挂着「在线」，等下次登录纠正 |
| `能力检测失败，error=…` | 算这台机器能干哪几件事时炸了 | `error` | 不影响连接上报，只是这轮没带能力档 |
| `已换取短票，account=…` | 每次连 AI 端前现换一张票 | `account` 记账用的账号标识 | 正常。**票据内容永不入日志** |
| `换票被拒绝，account=…，status=409，code=CLIENT_NOT_ONLINE` | 服务端拒签 | `code` 见契约 §5.3 九档 | `CLIENT_NOT_ONLINE` = 状态没同步，会自己好；`EMPLOYEE_AI_*` 要找管理员 |
| `换票请求失败，account=…，error=…` | 连不上业务端 | `error` | fail-closed：这位专员的自动化**停手**，不降级绕过 |
| `使用本地票据文件（仅供联调，生产禁用）` | 配了 `LOCAL_TICKET_FILE` | — | ⚠️ 生产环境看到这条 = 配置错了 |

### 1.1 微信消息事件（未回复跟进的事实来源）

契约见 `招聘分身_客户端微信消息事件上报_v1.md`。这一族回答「后端凭什么知道该不该追第二条」。
**只走流程不真动微信的机器一条都不出**（装配时就没建上报器）。

| 日志 | 什么时候出现 | 字段 | 看到之后 |
|---|---|---|---|
| `已登记微信消息事件，direction=inbound，来源=inbound_poll` | 刚读到候选人一条消息、或我方刚发出一条 | `direction` = `inbound`/`outbound`；`来源` = `inbound_poll`/`auto_reply`/`command` | 正常。事件先进本机发件箱，20 秒内报出去 |
| `微信消息事件已上报，direction=…，后端动作=schedule_follow_up，匹配到计划=True` | 后端收下了 | `后端动作` = 排跟进/取消跟进/无需动作；`匹配到计划=False` = 这个候选人名下没有在跑的计划 | 正常。`匹配到计划=False` 不是错，但说明这条事件没触发任何跟进 |
| `消息事件上报暂时失败，留着重试，status=503` | 网络抖、后端 5xx、或 401 会话被撤销 | `status` | 会重试，**用同一个 eventId**。本趟到此为止，剩下的下趟接着报 |
| `消息事件被后端拒收，不再重试，status=400` | 400/404/422 这类「我们发错了」 | `status`、`direction` | **不会重试**（重试一万次也一样）。要人看代码，字段肯定和契约对不上 |
| `消息事件反复报不出去，已放弃，attempts=20` | 同一条重试满 20 次 | `attempts` | 这条事件丢了：后端不会为它排/取消跟进 |
| `有消息事件超过保鲜期没能报出去，已丢弃，count=…` | 事件压了超过 24 小时 | `count` | 同上，且说明这台机器离线/没登录了很久 |
| `这个会话还没归位到候选人，入站消息不上报` | 本机不知道这个会话名对应哪个候选人 | `account` | **不是错**（契约要求归不了位就别报）。要它报出来，得先让 `/client/contacts` 把这个人归位 |
| `发出的回复没能归位到候选人，不上报消息事件` | 同上，出站那一侧 | `account` | 同上 |
| `微信任务没有确认成功，不上报消息事件，status=failed` | 队列任务没走到 `succeeded` | `op`、`status` | 这条消息**多半没发出去**，所以不报「已发送」。先查第 3 节那条失败 |
| `发送任务没有确认成功，status=failed，timed_out=False` | 自动回复投出去的那条任务没成功 | `status`、`timed_out`、`task_id` | 这一轮剩下的段落**不会再发**（结果不明不盲目续发），本批也不重投 |
| `入站消息事件登记失败，error=…` | 登记那一步自己炸了 | `error` | 收消息不受影响；这条事件丢了 |
| `退出时消息事件没清完，留到下次开机再报，pending=…` | 关程序时 2 秒没把发件箱清空 | `pending` 还剩几条 | 不算丢（发件箱落盘）；但这几条跟进要晚到下次开机之后 |
| `退出时清消息事件出错，error=…` | 退出那一下上报炸了 | `error` | 同上 |

## 2. 网关 ↔ AI 端（一轮对话）

| 日志 | 含义 |
|---|---|
| `已连接 AI 端` / `已为该账号建立 AI 端连接，account=…` | WebSocket 建好了。前者是连上，后者是这个账号的会话建好 |
| `旧会话接不回，改为新建，account=…` | 上次的会话续不上（服务端重启/过期），开了个新的。**新会话没有上一轮的上下文** |
| `AI 端连接不可用，account=…，error=…` | 连不上或断了，这一轮不回复 |
| `派发一轮给 AI 端，会话=张三，条数=3` | 把去抖聚合后的 N 条消息作为**一轮**发给 AI |
| `AI 端返回错误，account=…，code=…` | AI 端回了错误信封 |
| `已投递回复，account=…，会话=张三，segments=2` | 回复被拆成 2 段投递给微信执行器。**这是「已排队」，不是「已发出」**——真发出去看第 3 节 |
| `本轮不回复，account=…，会话=…，reason=…` | AI 判断这轮不该说话（转人工、拒绝、非工作时间等） |
| `出站被守门拦下，account=…，会话=…，reason=…` | 频次配额 / 时间窗 / 黑名单挡的。和「做不了」不同，这是「不让做」 |
| `按 AI 端提案拉黑，account=…` | AI 判定对方明确拒绝，之后不再自动触达 |
| `收到无法解析的帧` / `收到未处理的推送事件，ev=…` / `未归位的事件，ev=…` | 协议层面的意外帧，一般是两端版本不齐 |
| `读循环结束，error=…` | 这条 WS 读到头了（断线或主动关） |
| `监听列表已更新（AI 端推送），只管=N` | AI 端下发了「可以自动回复的人/群」名单 |
| `监听名单是空的，暂不处理任何会话` | **默认不动任何人**。名单没下来就一条都不回，这是安全默认 |
| `监听列表推送格式不对，忽略` | 推下来的名单结构不对，保持旧名单 |
| `节拍已更新（AI 端下发）` | 读消息/查好友的间隔被 AI 端改了 |
| `间隔过密，已抬到下限（防风控），what=…，配置=…，实际=…` | ⚠️ **下发的节拍比本机下限还快，已被强行抬回下限**。防风控红线，任何配置都压不过它 |

## 3. 微信侧动作（指令 → UIA 执行）

### 3.1 指令进来（`gateway/commands.py`）

| 日志 | 含义 |
|---|---|
| `指令已排期，op=send_message` | 收到指令，进队列 |
| `指令已执行过，直接回上次结果，op=…，status=…` | 幂等命中，**没有重复执行** |
| `收到不支持的微信指令，op=…` | 这个版本的网关没有这个能力 |
| `收到发文件指令但没配下载通道，op=…` | 取不到 AI 端产出的文件，发不了 |
| `这台电脑现在做不了这个动作，op=…，reason=…` | 能力表说不行（微信没登录、UIA 没暴露、联调模式） |
| `指令被守门拦下，op=…，reason=…` | 规则挡的（配额/时间窗/黑名单） |
| `取 AI 端产出文件失败，op=…，error=…` | 海报之类的产出物没取到 |
| `指令执行完成，op=…，dry_run=false` | ✅ 真做了。`dry_run=true` = **只走流程没真发** |
| `指令执行失败，op=…，error=…` | 执行阶段炸了 |

### 3.2 执行器（`queue/worker.py`）

| 日志 | 含义 |
|---|---|
| `微信任务执行器已启动，轮询间隔 N 秒` / `已停止` | 执行器生命周期 |
| `微信任务开始执行：发送消息 #a1b2c3d4` | 任务开跑。`#` 后是任务 ID 前 8 位，**用它串起同一条任务的全部日志** |
| `微信任务执行成功 / 执行失败 / 被阻止` | 三种收尾。`被阻止` = 规则不让做；`执行失败` = 做了没成 |
| `微信任务让出这一轮，稍后接着做` | 长任务主动让出，不占着执行器 |
| `跳过重复待执行任务` | 同类任务已在队列里 |
| `执行器租约丢失，已停手：任务 #…（执行器租约 丢、任务租约 在）` | ⚠️ **这条最要紧**：这条任务可能已被另一个执行器接走，再往下写就是两个进程同时操作同一个微信 |

### 3.3 真正碰微信的那一层（`wechat_api/uia.py`）

每个动作都是 `开始…` → `…完成` 或 `…失败` 三段。

| 动作 | 日志 |
|---|---|
| 加好友 | `开始添加好友：138…` → `好友申请已提交：138…（张三-仓库工）`。**「已提交」不等于「已是好友」**，对方点同意才算 |
| | `添加好友改走备用流程：…（这次读不到对方昵称）` / `添加好友失败：…，原因：…` |
| 查好友申请 | `开始检查好友申请：仅检查/并同意，最多 N 条` → `没有新的申请` / `发现 N 条` |
| 搜联系人 | `开始搜索联系人：X，最多 N 条` → `匹配 N 条，精确匹配 N 条` |
| 读资料 / 群成员 | `开始读取联系人资料：X` → `读取完成`；`开始读取群成员：X` → `共 N 人` |
| 发消息 | 见下方「发没发出去」 |
| 发文件 | `开始发送文件给「X」：共 N 个` → `文件发送完成` |
| 朋友圈 | `开始发布朋友圈：文字 N 字，媒体 N 个` → `发布成功` / `发布失败` / `媒体文件不存在` |
| 朋友圈点赞 | `开始给朋友圈点赞：只点今天的，最多 N 条` → `朋友圈点赞完成：点了 N 条，看过 N 条，已点过 N 条` / `朋友圈点赞失败：…` |
| 朋友圈评论 | `开始给朋友圈评论：要评 N 条，只评今天的` → `朋友圈评论完成：评了 N 条，看过 N 条，没认出 N 条` / `朋友圈评论失败：…` |
| 朋友圈巡看 | `开始巡看朋友圈：只看新动态，最多收 N 条，顺手点赞 N 个` → `朋友圈巡看完成：新动态 N 条，点了 N 个赞，已点过 N 个` / `朋友圈巡看失败：…`；循环侧 `朋友圈巡看一趟：…` / `朋友圈巡看这趟没成：…` / `这趟朋友圈巡看跳过：…` / `新动态已交给劳小智写评论` / `交给劳小智写评论没成：…` |
| 读消息 | `会话列表读取完成：共 N 个` / `未读消息汇总完成：N 个会话，共 N 条` / `聊天记录读取完成：X，共 N 条` |
| | `主窗口里读不了「X」，改用独立聊天窗口：…` |
| 窗口 | `已把微信窗口拉回前台（强制）` / `拉起微信窗口失败：…` |
| 探测 | `微信 UIA 探测完成：可用/不可用，原因：…`；`微信被最小化了，已把窗口拉起来重新探测：可用` |

**「发没发出去」这一组（真机上最值钱的几条）**

微信这边点了发送不代表发出去了，所以每次发完都回头核对输入框：

| 日志 | 含义 |
|---|---|
| `发送前后核对输入框：还剩 0 个字` | ✅ 输入框空了 = 确实发出去了 |
| `消息卡在输入框里没发出去：「张三」，输入框里还剩 12 个字——对方没有收到` | ❌ **明确没发出去**。任务会标失败，不会谎报成功 |
| `文件还在输入框里，第 2 次补按发送键：alt+s` | 正在补救 |
| `补按发送键失败，按「没发出去」处理：…` | 补救也没成 |
| `读不到输入框，这次发没发出去判定不了：…` | ⚠️ 结论**未知**：可能发了也可能没发，此时不会自动重试（重试会重复骚扰对方） |

## 4. 入站轮询（谁在说话）

| 日志 | 含义 |
|---|---|
| `不在工作时间窗，暂停轮询微信` / `进入工作时间窗，恢复轮询微信` | 非工作时间**完全不碰微信**（防风控红线） |
| `新消息，会话=张三，谁=对方，时间=14:03，内容=还招人吗` | 读到一条新消息。`谁` = `对方` 或 `我`（专员自己手打的） |
| `第一次读这个会话，只接尾部今天、对方发的那几条，更早的算历史不回溯` | 新会话的起点，避免把半年前的老消息当新消息回 |
| `读完这个会话，会话=…，读到=N` / `名单较长，本轮只读其中一段` | 一轮读取的收尾 |
| `名单里的这个会话读不到，先跳过，会话=…，原因=…` → `又能读了` | 会话暂时打不开（窗口被占、改名） |
| `游标在刚读到的记录里找不到，只对齐游标不回溯；连着出现说明游标机制失效了` | ⚠️ 连着出现要查——可能漏消息 |
| `入站取消息失败 / 处理入站消息失败，已留在待处理队列等下一趟重投` | 这一轮没处理成，**消息没丢**，下一趟重来 |
| `待处理消息超过保鲜期，已丢弃（这时候再回过去反而更奇怪）` | 隔太久了，不补回 |
| `从待处理队列补投，批次=N` | 补投欠账，排在读新消息之前（先来先回） |
| `有新好友申请待处理（不会自动通过），account=…，count=N` | 只提醒，**不自动同意** |
| `定时指令到点，开始执行` / `定时指令迟到太久，已放弃` | 定时任务 |

## 5. 进程与界面

| 日志 | 含义 |
|---|---|
| `桌面端已启动，real_actions=true` | `real_actions=false` = **联调模式，写操作只走流程不真发** |
| `网关启动，accounts=N` / `网关已停止` / `网关按请求停止` | 服务生命周期 |
| `网关启动失败 / 网关无法启动 / 网关异常退出，error=…` | 起不来或崩了。这时会向业务端上报 `client_error` |
| `界面卡了一下，stalled_ms=795，service=…，page=…` | 主线程被占住了多少毫秒。`stalled_ms` 越大越明显，**超过 ~200ms 人就能感觉到** |
| `已落地待发送文件，file_id=…，name=…，bytes=…` | 从 AI 端取回的产出物已存到本机 |
| `正在退出桌面端` / `收尾超时，强制退出` | 后者 = 没等到收口就走了 |

## 6. 什么会进日志、什么绝不进

**绝不进**（写代码时也不许加）：

- 客户端 Token 原文、AI 会话票据（票据只记「换到了」和 `account`）、密码、邮箱验证码。
- 微信 Cookie、UIA 控件树原文、窗口截图。

**会进，且是有意的**：

- **聊天内容会写进本机日志**，每条截断到 **40 字**（用户明确要求「最好把最近的消息日志也打印到实时日志中」）。这是专员自己那台电脑上的运维日志——但也正因为如此，`.wxclient/` 整个目录**禁止入库**，日志文件不要往外发。
- 会话名（微信备注名/群名）、手机号（加好友时）会出现在日志里。

## 7. 排障怎么串

| 想查 | 抓什么 |
|---|---|
| 一条消息为什么没发出去 | 搜会话名 → 看 `已投递回复`（排队）→ `微信任务开始执行 #xxxxxxxx` → 用这 8 位任务 ID 搜 → 看「发送前后核对输入框」那条 |
| 这台机器为什么显示离线 | 搜 `已上报客户端状态` 看最后一次报的是什么；再看有没有 `被拒`（带 `details`）或 `会话已被撤销` |
| 为什么一条都不回 | 搜 `监听名单是空的`、`不在工作时间窗`、`本轮不回复`、`出站被守门拦下` —— 四条各是一种「不该回」 |
| 界面卡 | 搜 `界面卡了一下`，看 `stalled_ms` 和当时的 `service`/`page` |
| 是不是在联调模式空转 | 搜 `real_actions` 和 `dry_run=true` |
