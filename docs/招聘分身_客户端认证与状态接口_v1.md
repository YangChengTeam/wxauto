# 招聘分身客户端认证与状态接口 v1

> 文档状态：待评审
>
> 适用范围：劳小智业务后端、Windows 招聘分身客户端、劳小智企业端
>
> 更新时间：2026-08-15

## 1. 目标

本文定义以下接口及状态口径：

1. Windows 招聘分身客户端使用邮箱和密码登录。
2. 服务端明确区分 Web 登录和招聘分身客户端登录。
3. 客户端登录不触发邮箱 OTP。
4. 客户端获得不设置自动过期时间、但可随时撤销的专用 Token。
5. 客户端在状态变化时主动回传在线、离线、异常以及微信 UIA 连接状态。
6. 企业端每 5 秒查询一次聚合状态，实时引导用户完成启用步骤。

本文只定义接口契约，不表示接口已经实现。

---

## 2. 核心设计结论

### 2.1 Web 与客户端必须使用不同登录接口

| 使用端 | 登录接口 | 邮箱 OTP | Token 类型 |
| --- | --- | --- | --- |
| 企业端 Web | `POST /auth/login` | 首次或异常登录需要 | 员工 Web 会话 Token |
| Windows 招聘分身客户端 | `POST /recruitment-agent/client/auth/login` | 不需要 | 招聘分身客户端专用 Token |

禁止在现有 `/auth/login` 中仅增加 `skipOtp=true`、`isClient=true` 等字段绕过 OTP。请求字段可以被任意调用方伪造，不能作为安全边界。

客户端专用接口签发独立 Token，并限制为只能访问 `/recruitment-agent/client/*`。该 Token 不得访问工资、合同、员工管理、企业配置等 Web 业务接口。

### 2.2 “不设置过期时间”不等于“无法失效”

客户端 Token 满足以下规则：

- 不设置自动过期时间，响应中的 `expiresIn` 和 `expiresAt` 均为 `null`。
- 使用至少 256 bit 随机强度的 opaque Token，不建议签发无 `exp` 的普通 JWT。
- 数据库只保存 Token 哈希，Token 原文只在登录成功响应中返回一次。
- 每次请求必须校验客户端会话仍为 `active`，不能只校验 Token 格式。
- 用户退出客户端、换设备、密码重置、账号停用、客户公司停用、管理员撤销会话或安全事件发生时立即失效。
- 客户端必须使用 Windows Credential Manager 或 DPAPI 保存 Token，禁止写入明文配置文件和日志。

### 2.3 状态按三个维度保存

不得只使用一个 `status` 同时表达客户端、微信和分身运行状态。服务端分别维护：

- `client.status`：客户端是否登录、在线或被撤销。
- `wechatUia.status`：招聘分身客户端与本机微信的 UI Automation 连接是否未建立、连接中、已连接、失败或断开。
- `agent.status`：招聘分身是否未启用、检测中、运行中、受限或暂停。

企业端使用服务端派生的 `stage` 决定当前引导步骤，同时保留 `clientOnline`、`wechatOnline` 和 `enabled` 兼容字段。

## 3. 通用约定

### 3.1 Base URL

本地环境：

```text
http://localhost:3001
```

以下接口路径均相对于业务后端 Base URL。

### 3.2 请求头

客户端登录接口：

```http
Content-Type: application/json
X-Request-Id: <uuid，可选>
```

客户端受保护接口：

```http
Authorization: Bearer <clientAccessToken>
Content-Type: application/json
X-Request-Id: <uuid，可选>
```

企业端状态查询接口继续使用普通员工 Web Token：

```http
Authorization: Bearer <employeeAccessToken>
```

### 3.3 字段格式

- JSON 字段统一使用 `camelCase`。
- 时间统一使用 UTC ISO 8601，例如 `2026-08-15T08:30:00.000Z`。
- `tenantId`、`userId` 和招聘分身归属均由服务端会话派生，客户端不得上传或覆盖。
- 所有状态查询响应必须返回 `Cache-Control: no-store`。

### 3.4 错误信封

```json
{
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "邮箱或密码错误",
    "details": {},
    "request_id": "0ee3c6a3-a14b-4386-8b9e-cf9179ac1249"
  }
}
```

登录失败不得区分“邮箱不存在”和“密码错误”。

## 4. 接口清单

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/recruitment-agent/client/auth/login` | Windows 客户端 | 邮箱密码登录，不触发 OTP |

## 5. 客户端邮箱密码登录

### 5.1 `POST /recruitment-agent/client/auth/login`

使用邮箱和密码登录 Windows 招聘分身客户端。该接口不创建邮箱 OTP Challenge，也不返回 `challengeRequired`。

#### 请求体

```json
{
  "email": "hr@example.com",
  "password": "用户输入的密码",
  "clientType": "recruitment_agent_windows",
  "deviceId": "本次安装生成的稳定随机设备标识",
  "deviceName": "陈敏的办公电脑",
  "clientVersion": "1.0.0",
  "osVersion": "Windows 11 23H2",
  "replaceExistingSession": false
}
```

#### 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `email` | 是 | 去除首尾空格并转为小写后匹配账号 |
| `password` | 是 | 不得写入日志、埋点或错误详情 |
| `clientType` | 是 | 固定为 `recruitment_agent_windows`；用于审计和契约校验，不单独构成安全边界 |
| `deviceId` | 是 | 客户端首次安装生成，20–128 位 URL-safe 随机字符串；不得使用 MAC、硬盘序列号等硬件隐私标识 |
| `deviceName` | 是 | 1–120 字符，仅用于用户识别设备 |
| `clientVersion` | 是 | 客户端语义版本号 |
| `osVersion` | 否 | 最长 120 字符 |
| `replaceExistingSession` | 否 | 默认 `false`；为 `true` 时撤销该用户已有招聘分身客户端会话并登录当前设备 |

#### 服务端处理

1. 校验参数、账号密码、账号状态和客户公司状态。
2. 复用现有密码失败计数和锁定规则。
3. 不执行 `riskReason -> email OTP` 流程；安全策略仍可以直接拒绝登录。
4. 确认该用户存在且只存在一个可用招聘分身。
5. 确认当前用户没有关联其他启用中的招聘分身。
6. 如已有其他设备的活动客户端会话且未确认替换，返回 `409 ACTIVE_CLIENT_SESSION_EXISTS`。
7. 创建客户端专用会话，签发 scope 受限的 opaque Token。
8. 将客户端状态更新为 `online`，微信 UIA 状态保持原值或初始化为 `not_connected`。
9. 写入登录成功审计事件，不记录密码和 Token 原文。

#### 登录成功响应 `200`

```json
{
  "accessToken": "lxz_rc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "tokenType": "Bearer",
  "expiresIn": null,
  "expiresAt": null,
  "sessionId": "f5384291-14a4-44ca-ad69-9f17123550d6",
  "scope": [
    "recruitment_agent:client"
  ],
  "clientType": "recruitment_agent_windows",
  "user": {
    "id": "b67d1bf8-40d3-4883-8429-0131572118f7",
    "name": "陈敏",
    "email": "hr@example.com"
  },
  "agent": {
    "id": "10f9d1cb-8031-4661-902d-871f93910f9c",
    "name": "陈敏的招聘分身"
  },
  "activationStatus": {
    "stage": "waiting_wechat_uia_connection",
    "enabled": false,
    "clientOnline": true,
    "wechatOnline": false,
    "updatedAt": "2026-08-15T08:30:00.000Z"
  }
}
```

#### 已有其他客户端会话 `409`

```json
{
  "error": {
    "code": "ACTIVE_CLIENT_SESSION_EXISTS",
    "message": "该招聘分身已在另一台电脑登录，请确认是否切换到当前电脑",
    "details": {
      "deviceName": "Windows-陈敏办公电脑",
      "lastSeenAt": "2026-08-15T08:29:55.000Z",
      "canReplace": true
    }
  }
}
```

客户端获得用户明确确认后，将 `replaceExistingSession` 改为 `true` 重新请求。服务端撤销旧会话后，旧 Token 必须立即失效，旧设备上未执行的动作不得自动转移到新设备。

#### 登录接口错误码

| HTTP | code | 含义 |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | 参数格式错误 |
| `401` | `INVALID_CREDENTIALS` | 邮箱或密码错误 |
| `403` | `ACCOUNT_UNAVAILABLE` | 员工账号不可用 |
| `403` | `TENANT_UNAVAILABLE` | 客户公司不可用或已过期 |
| `403` | `CLIENT_LOGIN_DENIED` | 客户端登录被安全策略拒绝 |
| `409` | `AGENT_NOT_PROVISIONED` | 当前用户尚未开通招聘分身 |
| `409` | `AGENT_ASSOCIATION_CONFLICT` | 当前用户或招聘分身存在冲突关联 |
| `409` | `ACTIVE_CLIENT_SESSION_EXISTS` | 另一台设备已有活动会话 |
| `423` | `ACCOUNT_LOCKED` | 账号因连续登录失败临时锁定 |
| `426` | `CLIENT_UPGRADE_REQUIRED` | 客户端版本过低，必须升级 |
| `429` | `RATE_LIMITED` | 登录请求过于频繁 |

### 5.2 Token 内容与权限

客户端 Token 对应的服务端会话至少包含：

```text
session_id / actor_id / tenant_id / agent_id / device_id
token_hash / client_type / client_version / status
created_at / last_seen_at / revoked_at / revoked_reason
user_auth_version / tenant_auth_version
```

客户端 Token 只能访问：

```text
/recruitment-agent/client/*
```

禁止访问：

```text
/payroll/*
/attendance/*
/users/*
/tenant/*
/auth/sessions/*
其他普通员工 Web 接口
```

即使客户端 Token 没有自动过期时间，服务端也必须在每次请求时校验：

1. 会话状态为 `active`。
2. 员工账号和客户公司仍可用。
3. `userAuthVersion` 和 `tenantAuthVersion` 未变化。
4. Token 中的 `agentId` 仍归属于当前用户。
5. 当前设备仍为该分身的活动设备。

## 6. 客户端退出

### 6.1 `POST /recruitment-agent/client/auth/logout`

撤销当前客户端会话和 Token。

#### 请求

无请求体，使用客户端 Bearer Token。

#### 响应 `200`

```json
{
  "success": true,
  "clientStatus": "revoked",
  "agentStatus": "not_enabled"
}
```

退出后必须停止接收新动作；未执行动作重新进入服务端待调度状态，不允许继续使用旧 Token 上报结果。

## 7. 客户端状态修改

### 7.1 `PUT /recruitment-agent/client/status`

客户端不发送定时心跳，只在运行状态发生变化时调用本接口。

登录成功后，服务端自动将客户端状态设置为 `online`，客户端不需要立即重复上报。正常退出、主动断开或发生影响运行的异常时，客户端必须修改状态。

#### 请求体

```json
{
  "eventId": "1cc03e68-8842-4e11-a95c-bca643434dd6",
  "status": "offline",
  "clientVersion": "1.0.0",
  "reason": "client_shutdown",
  "occurredAt": "2026-08-15T08:30:05.000Z"
}
```

#### `client.status` 枚举

| 状态 | 含义 | 典型触发时机 |
| --- | --- | --- |
| `online` | 客户端已登录并可继续工作 | 登录成功、异常恢复或重新连接完成 |
| `offline` | 客户端已主动停止工作 | 正常退出、用户主动断开 |
| `error` | 客户端仍有会话，但发生阻断运行的异常 | UIA 初始化失败、运行环境异常 |

`revoked` 由服务端在会话撤销时设置，客户端不得主动上报。

#### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `eventId` | 是 | UUID 幂等键；重复事件不得重复写入状态和审计 |
| `status` | 是 | `online`、`offline` 或 `error` |
| `clientVersion` | 是 | 当前客户端版本 |
| `reason` | 否 | 稳定机器原因码，例如 `client_shutdown`、`runtime_error` |
| `occurredAt` | 是 | 客户端记录的状态变化时间；最终接收时间以服务端为准 |

#### 响应 `200`

```json
{
  "accepted": true,
  "clientStatus": "offline",
  "stage": "client_offline",
  "updatedAt": "2026-08-15T08:30:05.120Z"
}
```

#### 无心跳时的状态边界

- 服务端不按时间自动把 `online` 改为 `offline`。
- `clientOnline` 表示客户端最后一次明确上报的状态为 `online`，不是实时存活探测结果。
- 正常退出和主动断开必须先上报 `offline`，再结束进程。
- 进程崩溃、系统强制结束、电脑断电或网络突然中断时，客户端无法上报，服务端可能继续保留最后一次 `online` 状态。
- `lastStatusAt` 必须返回最后一次状态修改时间，企业端可展示“最后更新于”，但不得自行按时间推断离线。
- 收到被撤销 Token 时返回 `401 CLIENT_SESSION_REVOKED`，客户端必须清除本地 Token 并回到登录页。

## 8. 微信 UIA 连接状态上报

### 8.1 `PUT /recruitment-agent/client/wechat-uia/status`

招聘分身客户端通过 Windows UI Automation（UIA）连接本机已经运行并登录的微信客户端。劳小智不负责微信账号登录，不接收微信密码、二维码或登录票据。

UIA 连接状态发生变化时立即调用本接口，相同状态不重复上报。

#### 请求体：开始建立 UIA 连接

```json
{
  "eventId": "82c6f035-5843-422f-8784-335417129aba",
  "status": "connecting",
  "occurredAt": "2026-08-15T08:31:00.000Z"
}
```

#### 请求体：UIA 连接成功

```json
{
  "eventId": "c05281af-38f3-4afe-9759-f662297120bd",
  "status": "connected",
  "wechatInstance": {
    "accountRef": "连接器生成的稳定不透明账号标识",
    "nickname": "陈敏招聘",
    "accountMask": "wxid_****8a2f",
    "processVersion": "4.0.1.15"
  },
  "occurredAt": "2026-08-15T08:31:18.000Z"
}
```

#### 请求体：UIA 连接失败

```json
{
  "eventId": "610eea17-02b8-42fa-ab8b-0068f65dc6db",
  "status": "failed",
  "failure": {
    "code": "WECHAT_UIA_PROCESS_NOT_FOUND",
    "message": "未检测到正在运行的微信，请先打开并登录 PC 微信",
    "retryable": true
  },
  "occurredAt": "2026-08-15T08:32:00.000Z"
}
```

#### 字段说明

| 字段 | 说明 |
| --- | --- |
| `eventId` | UUID，作为幂等键；重复事件返回同一结果，不重复写审计 |
| `status` | 微信当前状态，见下方枚举 |
| `wechatInstance.accountRef` | 连接器生成的稳定不透明账号标识，用于检查一个微信是否被多个分身占用；不得直接展示 |
| `wechatInstance.nickname` | 当前 PC 微信昵称，按最小必要原则保存和展示 |
| `wechatInstance.accountMask` | 已脱敏微信账号标识 |
| `wechatInstance.processVersion` | 当前 PC 微信客户端版本，用于兼容性判断 |
| `failure.code` | 稳定机器错误码 |
| `failure.message` | 可向用户展示的恢复提示，不得包含凭证或内部堆栈 |
| `failure.retryable` | 是否允许用户直接重试 |

#### `wechatUia.status` 枚举

| 状态 | 含义 |
| --- | --- |
| `not_connected` | 客户端在线，但尚未连接本机微信 UIA |
| `connecting` | 正在查找微信进程、主窗口和 UIA 控件树 |
| `connected` | 已与本机微信建立 UIA 连接 |
| `failed` | 本次 UIA 连接失败，必须同时返回 `failure` |
| `disconnected` | 曾连接成功，但 UIA 连接已断开 |

#### 微信失败码

| code | 用户提示建议 | 是否可重试 |
| --- | --- | --- |
| `WECHAT_UIA_PROCESS_NOT_FOUND` | 未检测到正在运行的微信，请先打开并登录 PC 微信 | 是 |
| `WECHAT_UIA_ACCOUNT_NOT_LOGGED_IN` | PC 微信尚未登录，请完成微信登录后重新连接 | 是 |
| `WECHAT_UIA_WINDOW_UNAVAILABLE` | 未找到可连接的微信主窗口，请重启 PC 微信后重试 | 是 |
| `WECHAT_UIA_PERMISSION_DENIED` | 无法访问微信窗口，请以相同权限级别运行两个客户端 | 是 |
| `WECHAT_UIA_VERSION_UNSUPPORTED` | 当前微信版本暂不支持，请升级招聘分身客户端 | 否 |
| `WECHAT_UIA_CONNECT_TIMEOUT` | 连接微信超时，请重启 PC 微信后重试 | 是 |
| `WECHAT_UIA_CONNECTION_LOST` | 微信 UIA 连接已断开，请检查 PC 微信运行状态 | 是 |
| `WECHAT_UIA_ACCOUNT_IN_USE` | 当前微信已被其他招聘分身占用 | 否 |
| `CAPABILITY_CHECK_FAILED` | 微信已连接，但能力检测未通过 | 是 |

#### 成功响应 `200`

```json
{
  "accepted": true,
  "wechatUiaStatus": "connected",
  "agentStatus": "checking",
  "stage": "checking_capabilities",
  "updatedAt": "2026-08-15T08:31:18.100Z"
}
```

#### 微信实例占用冲突 `409`

```json
{
  "error": {
    "code": "WECHAT_UIA_ACCOUNT_IN_USE",
    "message": "当前微信已被其他招聘分身占用，请先断开原连接",
    "details": {
      "accountMask": "wxid_****8a2f"
    }
  }
}
```

服务端必须保证：一个启用中的招聘分身同一时刻只能连接一个 PC 微信实例，一个 PC 微信账号同一时刻只能被一个启用中的招聘分身占用。

## 9. 企业端聚合状态查询

### 9.1 `GET /recruitment-agent/activation-status`

企业端 Web 使用普通员工 Token 调用。服务端只返回当前登录用户自己的招聘分身状态，不接收 `tenantId` 或 `userId` 查询参数。

企业端未启用页面建议每 5 秒轮询一次；进入运行中工作台后可降低频率或改用事件推送。

#### 完整响应 `200`

```json
{
  "stage": "waiting_wechat_uia_connection",
  "enabled": false,
```

## 10. 聚合阶段 `stage`

`stage` 由服务端根据三个维度状态统一派生，前端不得自行拼装业务规则。

| stage | 用户界面文案 | 触发条件 |
| --- | --- | --- |
| `waiting_client_login` | 登录招聘分身客户端 | 尚无有效客户端会话 |
| `client_logged_in` | 客户端登录成功 | 客户端刚登录，等待下一状态 |
| `waiting_wechat_uia_connection` | 连接本机微信 | 客户端在线，尚未建立微信 UIA 连接 |
| `wechat_uia_connecting` | 正在连接本机微信 | 微信 UIA 状态为 `connecting` |
| `wechat_uia_connected` | 微信 UIA 连接成功 | UIA 已连接，尚未完成能力检测 |
| `wechat_uia_failed` | 微信 UIA 连接失败 | 微信 UIA 状态为 `failed` |
| `checking_capabilities` | 正在检测微信能力 | 微信在线，能力检测进行中 |
| `capability_limited` | 部分能力不可用 | 能力检测完成但存在受限项 |
| `running` | 招聘分身运行中 | 客户端在线、微信在线、能力通过且未暂停 |
| `client_offline` | 招聘分身客户端离线 | 客户端明确上报 `offline` |
| `client_error` | 招聘分身客户端异常 | 客户端明确上报 `error` |
| `wechat_uia_disconnected` | 微信 UIA 连接已断开 | 客户端在线，但之前建立的 UIA 连接已断开 |
| `paused` | 招聘分身已暂停 | 用户或系统暂停分身 |
| `client_login_expired` | 客户端登录已失效 | 会话被撤销或账号安全版本变化 |

### 10.1 状态优先级

同时满足多个异常条件时，服务端按以下优先级返回 `stage`：

```text
client_login_expired
→ paused
→ client_error
→ client_offline
→ waiting_client_login
→ wechat_uia_failed
→ wechat_uia_disconnected
→ wechat_uia_connecting
→ waiting_wechat_uia_connection
→ checking_capabilities
→ capability_limited
→ running
```

## 11. 客户端会话管理

长期 Token 必须配套可见、可撤销的设备会话管理。

### 11.1 `GET /recruitment-agent/client-sessions`

使用企业端员工 Token，返回当前用户自己的客户端会话。

```json
{
  "items": [
    {
      "sessionId": "f5384291-14a4-44ca-ad69-9f17123550d6",
      "deviceId": "QkXQYp3p5zNfXk0nB0M0NA",
      "deviceName": "陈敏的办公电脑",
      "clientVersion": "1.0.0",
      "status": "active",
      "online": true,
      "createdAt": "2026-08-15T08:30:00.000Z",
      "lastSeenAt": "2026-08-15T08:35:00.000Z"
    }
  ]
}
```

### 11.2 `DELETE /recruitment-agent/client-sessions/:sessionId`

撤销指定客户端会话。只能撤销当前用户自己的招聘分身客户端会话。

```json
{
  "success": true,
  "sessionId": "f5384291-14a4-44ca-ad69-9f17123550d6",
  "revokedAt": "2026-08-15T08:36:00.000Z"
}
```

会话撤销后：

1. 旧 Token 立即返回 `401 CLIENT_SESSION_REVOKED`。
2. 分身暂停接收和执行新动作。
3. 企业端状态变为 `client_login_expired`。
4. 审计日志记录操作者、设备、时间和撤销原因。

## 12. 数据模型建议

### 12.1 `recruitment_agent_client_sessions`

```text
id / tenant_id / user_id / agent_id
device_id / device_name / client_type / client_version / os_version
token_hash / scope / status
user_auth_version / tenant_auth_version
created_at / last_seen_at / revoked_at / revoked_reason
```

约束：

- `token_hash` 唯一。
- 同一 `agent_id` 同一时刻最多一个 `active` 客户端会话。
- Token 原文永不入库。

### 12.2 `recruitment_agent_runtime_status`

```text
agent_id / client_session_id
client_status / client_last_status_at / client_status_reason
wechat_uia_status / wechat_account_ref_hash / wechat_nickname / wechat_account_mask
wechat_process_version / wechat_uia_failure_code / wechat_uia_failure_message / wechat_uia_failure_retryable
capability_status / agent_status / paused_reason
updated_at / version
```

### 12.3 `recruitment_agent_status_events`

```text
event_id / tenant_id / user_id / agent_id / client_session_id
event_type / from_status / to_status / failure_code
occurred_at / received_at / metadata
```

`event_id` 唯一，用于状态上报幂等。`metadata` 禁止保存 Token、微信密码、Cookie、UIA 控件树原文、窗口截图或完整私人通讯录。

## 13. 审计与安全要求

必须记录以下事件：

- 客户端登录成功、失败、锁定和安全拒绝。
- 新设备替换旧设备。
- 客户端退出和企业端撤销客户端会话。
- 微信 UIA 开始连接、连接成功、连接失败、连接断开和实例占用冲突。
- 能力检测成功、失败和能力变化。
- 分身启用、暂停和恢复。

禁止记录：

- 用户密码、OTP、客户端 Token 原文。
- 微信明文密码、Cookie、UIA 控件树原文、窗口截图和与招聘无关的界面内容。
- 与招聘无关的私人通讯录和私人聊天内容。

客户端登录虽然不需要 OTP，但仍必须具备：

- 邮箱、IP、设备组合限流。
- 统一登录失败文案。
- 连续失败锁定。
- 最低客户端版本控制。
- 独立 Token scope。
- 活动设备唯一约束。
- 用户和管理员可撤销会话。

## 14. 前端展示建议

企业端按 `stage` 展示主要状态，不重复展示多个同义状态：

| stage | 顶部状态 | 步骤 01 | 步骤 02 |
| --- | --- | --- | --- |
| `waiting_client_login` | 等待客户端连接 | 待完成 | 待完成 |
| `client_logged_in` / `waiting_wechat_uia_connection` | 客户端已连接 | 连接成功 | 待连接 |
| `wechat_uia_connecting` | 正在连接本机微信 | 连接成功 | 连接中 |
| `wechat_uia_connected` / `checking_capabilities` | 微信 UIA 已连接 | 连接成功 | 已连接 |
| `wechat_uia_failed` | 微信 UIA 连接失败 | 连接成功 | 显示失败原因和重试引导 |
| `running` | 招聘分身运行中 | 连接成功 | 已连接 |
| `client_offline` | 客户端已离线 | 连接中断 | 保留最近 UIA 状态 |
| `client_error` | 客户端运行异常 | 运行异常 | 保留最近 UIA 状态 |
| `wechat_uia_disconnected` | 微信 UIA 连接已断开 | 连接成功 | 重新连接 |

失败状态必须同时提供原因和恢复动作，不能只显示“连接失败”。

## 15. 验收标准

1. Web `/auth/login` 的 OTP 规则保持不变。
2. 客户端登录接口永不返回邮箱 OTP Challenge。
3. 客户端 Token 不包含自动过期时间，但退出、换设备、密码重置、账号停用和管理员撤销后立即失效。
4. 客户端 Token 无法访问普通员工 Web 业务接口。
5. 同一用户只允许一个活动招聘分身客户端会话。
6. 同一招聘分身同一时刻只能连接一个 PC 微信实例，同一 PC 微信账号不能被多个启用中的招聘分身占用。
7. 客户端不发送定时心跳；登录成功自动标记在线，正常退出、主动断开和运行异常通过状态接口显式修改。
8. 微信 UIA 连接成功、失败和连接断开能在企业端状态接口中明确区分。
9. 微信失败响应包含稳定错误码、用户可读说明和是否可重试。
10. 企业端只根据服务端 `stage` 展示主引导，不自行推导跨维度业务规则。
11. 状态事件重复上报保持幂等，不重复写入连接关系和审计记录。
12. 日志、数据库和错误响应中不存在密码、Token、微信 Cookie、UIA 控件树原文或窗口截图。
13. 文档和页面明确说明：无心跳时，进程崩溃、断电或网络突然中断可能保留最后一次在线状态，服务端不按时间自行推断离线。
